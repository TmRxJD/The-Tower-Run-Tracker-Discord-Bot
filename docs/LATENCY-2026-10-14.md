Previous patches showed a special `(comparison unavailable)` annotation for BH/orbs, while ordinary metrics could include the just-saved selected run as their own reference and display a misleading `(+0.00%)`.

## Follow-up: narrower review reads and reuse constraints

Additional bounded repairs were implemented after the first deployment:

1. Review duplicate detection now requests main records only. The duplicate predicate consumes tier, wave, duration, coins and run/local references; extended statistics are unused there. All main pages, final counts and ownership validation remain. Main-only snapshots are prohibited from local hydration and have a separate in-flight key from full-history reads.
2. If duplicate detection is disabled (or the run already has an explicit run reference), review does not request cloud history.
3. Submission hydration now uses the existing `yieldToEventLoop()` helper (`setImmediate`) instead of `setTimeout(0)`. A standalone 54-yield Windows measurement was 797.7 ms versus 0.46 ms. This preserves an I/O opportunity after each batch without waiting for the Windows timer interval.

### Why completed snapshots are not reused for submission/share

- A local per-user lock serializes this process, not website/other-instance mutations. Reusing the review snapshot could miss a new duplicate or external edit; reusing the submission snapshot for share could publish a deleted/stale selected run.
- The existing delta-function result contains runs, count, syncedAtMs and nextPage, not a complete remote-deletion set or an authoritative revision spanning both run halves. Background authority reconciliation separately enumerates IDs/counts. An unchanged count cannot detect same-count replacement, and a main-only latest timestamp cannot establish extended-half freshness.
- A point read of the selected share run would establish its existence but not current retained type counts, comparison reference runs or chart input. A main-only snapshot omits extended metrics needed by those consumers. Further narrowing is possible in principle, but requires a defined shared query contract for those dependent views; claiming a TTL cache is equivalent would weaken current checks.
- Exact equality filters on raw duplicate fields are not equivalent to the shared normalized duplicate predicate across legacy numeric/unit/duration formats. The main-only scan avoids introducing false negatives or requiring new normalized attributes/indexes.
